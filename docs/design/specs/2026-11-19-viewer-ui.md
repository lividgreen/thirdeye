# The viewer's look — design

**Date:** 2026-11-19
**Status:** draft, for the owner's review

---

## 1. Context

The viewer works, but its presentation is the PoC's: a heavy box, kinds as
comma-joined words, no sense of time, and a detail pane that splits a side
pane into two halves too narrow to read. Publishing to crates.io and winget,
the README's screenshots and a post on livid.work all wait for a viewer that
looks finished.

This round changes the ratatui head and adds a few fields to the protocol. It
changes nothing about what is captured, how it is ranked, or when the viewer
opens.

## 2. Decisions

Made by the owner on 2026-11-19:

- **A richer turn list.** Turns stay the structure. Each file row shows its
  name, its directory, what the agent did, how long ago, and whether it
  changed on disk since the agent last read it.
- **An adaptive detail.** In a pane narrower than 100 columns, an open file
  takes the whole pane; in a wider one, it sits beside the list.
- **A status line, a help overlay, a colour theme taken from the logo, and a
  modern look with thin frames.**

Not in this round: syntax highlighting (a large dependency, for a pane that
mostly shows a few lines around an edit), a session-wide "hot files" view,
and the mouse.

## 3. The screen

At a typical side-pane width, about 60 columns:

```
╭ thirdeye · thirdeye-test ───────────────────────╮
│ ● 3  fix the off-by-one in the parser   4   now │
│   ★ parser.rs       src/         E R        2m  │
│     └ the bug was here, not the lexer           │
│     parse.rs        tests/       W          1m  │
│     lexer.rs        src/           R  ⚠     3m  │
│ ▸ 2  where is the input parsed?         6   12m │
│ ▸ 1  set up the workspace               2   30m │
│                                                 │
╰─────────────────────────────────── claude · any ╯
 ↑↓ move  ⏎ open  d diff  q hide  ? help
```

- **One thin frame** (rounded corners, a muted colour) around the list. Its
  top edge carries `thirdeye · <workspace name>`; its bottom edge, right
  aligned, the agent and the policy. Nothing else is boxed.
- **The key line** sits under the frame, dim. A transient message (the
  `status` the head already keeps) replaces it for a few seconds.
- **The cursor** is a full-width row in a subtle background colour, not
  reverse video, which flattens every colour on the row.

### 3.1 Turn rows

`● 3  <prompt>  <files>  <age>`

- `●` in amber marks the turn in progress; a closed turn shows its fold
  arrow, `▸` folded or `▾` open. A turn in progress is never folded by
  default.
- The prompt is its first line, cut with `…` to fit. A turn with no prompt
  (the unattributed bucket, or an agent whose hooks carry none) reads
  `(no prompt recorded)`, dim.
- The file count and the age of the turn's latest event are right aligned.

### 3.2 File rows

`★ <name>  <directory>  <badges>  <⚠>  <age>`

- `★` in amber for a flagged file, and its reason on the next row, `└ …`,
  dim amber, cut to one line. The full reason is in the detail's header.
- **The name** in the normal colour, bold if the agent changed the file;
  **the directory**, workspace-relative, dim. When the row is too narrow,
  the directory is shortened from the left (`…/src/`) and then dropped; the
  name is cut last.
- **Badges**, one letter each, in fixed columns so they line up down the
  list: `E` edit, `W` write, `D` delete (changes, in mint; `D` in red), `R`
  read, `S` search, `X` a command, `M` a mention (in grey-blue). A flag is
  the star, not a badge.
- **`⚠`** in amber when the file changed on disk after the agent last read
  it (§5). Unknown staleness shows nothing: the indicator never claims a file
  is fresh, it only claims one is not.
- **The age** of the file's latest event in this turn: `now`, `12s`, `3m`,
  `2h`, `1d`.
- **Order within a turn:** flagged first, then changed files, then the rest;
  within each, the most recently touched first. Today's order is
  alphabetical, which puts the file the agent is working on wherever its name
  falls.

### 3.3 The detail

Below 100 columns the detail replaces the list; `Esc` brings the list back
with the cursor where it was. At 100 columns or more, the list takes 40% and
the detail 60%.

```
╭ src/parser.rs · content · 57–63 ──────────────────╮
│ the bug was here, not the lexer                    │
│   55  fn parse(input: &str) -> Ast {               │
│   56      let mut i = 0;                           │
│   57▌     while i <= input.len() {                 │
│   58▌         …                                    │
╰──────────────────────────────────────── 57/212 ───╯
 ↑↓ scroll  d diff  esc back  ? help
```

- The frame's title is the workspace-relative path, the mode, and the
  touched range; a flagged file's reason is the first row.
- The touched lines carry an amber bar in the gutter and amber line numbers.
- A diff colours added lines mint, removed lines red, hunk headers grey-blue,
  and still shows no line numbers of its own.
- The bottom edge shows the position, `57/212`.

### 3.4 Help

`?` opens a centred, framed overlay over whatever is showing: every key, and
a legend for `●`, `▸`, `★`, `⚠` and each badge. `?` or `Esc` closes it.

## 4. Colour

Taken from the logo, and used sparingly: colour marks something, it does not
decorate.

| Role | Truecolor | 16-colour fallback |
|---|---|---|
| Flag, turn in progress, touched lines, `⚠` | amber `#f2b84b` | yellow |
| Changes: `E`, `W`, diff additions | mint `#88ebb8` | green |
| Deletions: `D`, diff removals | red `#f07178` | red |
| Reads and the rest: `R`, `S`, `X`, `M`, hunk headers | grey-blue `#9aa7b6` | cyan |
| Directories, ages, frames, the key line | dim grey `#6b7686` | dark grey |
| Cursor row background | `#263247` | dark grey |

- Truecolor when `COLORTERM` is `truecolor` or `24bit`, the 16-colour column
  otherwise.
- **No background colour** anywhere but the cursor row, so the viewer takes
  the terminal's own, light or dark.
- **`NO_COLOR`** set to anything turns colour off. The star, the badges, `⚠`
  and the gutter bar still carry every meaning on their own.

## 5. What the daemon adds

Additive fields, so an older head ignores them and a newer head reads their
absence as "unknown":

- `FileView.last_touched`, the timestamp of the file's latest event in that
  turn. The head renders the age from it, and re-renders every few seconds
  so ages advance without a patch.
- `FileView.stale`, true when the file changed on disk after the agent last
  read or wrote it (the tracker's `Staleness::Modified`). False otherwise,
  including when it cannot tell.
- `Snapshot.agent`, the agent's id, for the bottom edge.

Staleness depends on the disk, not on the log, so the daemon recomputes it on
the timer it already runs (the agent-process poll, every 5 s) and sends a
patch only for files whose value changed. It stays derived: a restarted
daemon computes the same values from the same disk.

## 6. Tests

All in the existing style: state tests without a terminal, render tests on
ratatui's `TestBackend`.

- Each element above at 50, 80 and 120 columns, including the shortened and
  dropped directory and the cut prompt.
- The adaptive detail on either side of 100 columns.
- Ordering within a turn.
- **Perturbation tests** for the new indicators, as `CLAUDE.md` asks: `⚠`
  goes red on a planted on-disk change and stays absent for a file the agent
  just wrote; the age goes red on a planted timestamp.
- `NO_COLOR` produces a buffer with no colour in it.
